## 二、待建 — Google Sheets

### 1. `設定` 分頁（gid=764465026）加兩欄

現有欄位：`姓名 / 業務代碼 / 最新流水號 / email / 管理`，往後加：

| 欄位 | 內容 | 說明 |
|---|---|---|
| `訂閱方案` | 手動填 `完整` / `陽春` / `未訂閱` / `停用` | **空白一律視為 `完整`**，避免漏填就把人擋掉 |
| `本週已用` | 公式（見下） | 自動算，不用手動維護 |

**`訂閱方案` 這一欄就是「名單標記介面」**——直接在 Sheets 改那一格即可，不用另外做後台。

`本週已用` 的公式（假設 `業務代碼` 在 B 欄，這是第 2 列的寫法，往下拉）：

```
=IF($B2="",0,IFERROR(COUNTUNIQUEIFS('報刀單格式'!$A:$A,
  '報刀單格式'!$A:$A,">="&$B2&TEXT(TODAY()-WEEKDAY(TODAY(),3),"yymmdd"),
  '報刀單格式'!$A:$A,"<="&$B2&TEXT(TODAY()-WEEKDAY(TODAY(),3)+6,"yymmdd")&"99"),0))
```

原理跟你現有的 `最新流水號` 一樣，都是讓 Sheets 自己從 `報刀單格式` 算：

- `TODAY()-WEEKDAY(TODAY(),3)` ＝ 本週一（`WEEKDAY` 第二參數用 3 時，週一=0）
- 流水號前 2 碼是業務代碼、3~8 碼是**送出日期**，所以用字串範圍就能框出「這個人本週送出的流水號」
- 用 `COUNTUNIQUEIFS` 而不是 `COUNTIFS`：一張報刀單有幾個品項就有幾列、共用同一個流水號，**要算不重複的流水號才等於「幾張單」**
- 每週一自動歸零，不需要任何重設動作

> ⚠️ **這條公式是我唯一沒辦法在這邊實測的東西**（沒有 Google Sheets 環境）。貼上去後請先驗一次：找一個本週有報刀的人，把他的 `本週已用` 跟總表上該人本週的單數對一下。若數字不對跟我說，我再調。

## 三、待建 — Webhook `/webhook/ack-subscription`

前端已經在送這個 request（按下「我知道了」時）：

```json
{
  "token": "...",
  "公告代號": "sub-2026-09",
  "帳號": "derek",
  "姓名": "Derek",
  "確認時間": "2026-09-14 17:17",
  "裝置": "Mozilla/5.0 ..."
}
```

Node 流程：**Webhook（POST, path=`ack-subscription`）→ Google Sheets（Append，目標分頁 `訂閱確認紀錄`）**。

欄位直接對應（比照 `寫入作廢紀錄` node 的寫法）：

```
公告代號 = {{ $json.body['公告代號'] }}
帳號     = {{ $json.body['帳號'] }}
姓名     = {{ $json.body['姓名'] }}
確認時間 = {{ $json.body['確認時間'] }}
裝置     = {{ $json.body['裝置'] }}
```

> 每天按一次就記一筆（不是只記第一次）。重複曝光的紀錄愈多，日後「我不知道要收費」愈站不住腳。
> 不需要 Respond node，前端不等回應。

## 四、`google-login` 不用改

原本規劃讓登入回傳訂閱方案，但看過 workflow 後不需要：

- `google-login` 的授權名單是 Code node 裡**寫死的 `EMAIL_USERS` 陣列**，不讀 Google Sheets。
  要讓它知道訂閱方案，得加一個 Sheets 讀取 node 到登入流程裡——**登入是最不該增加失敗點的地方**。
- 改用「送出成功時順便回傳剩餘額度」，前端存 localStorage 下次顯示。
  效果一樣，但完全不動登入流程，也不用多做一支查額度的 webhook。

> 唯一的代價：使用者換裝置後，第一次報刀前看不到額度標籤（送出一次後就有了）。
> 真正的把關本來就在後端，前端只是提早告知，所以這個代價可以接受。

## 五、待建 — `manual-baodao` 額度控管（含一個既有嚴重 bug 的修正）

### 🔴 順便要修的既有 bug：Nick／Ian／Jason 現在報刀會整筆消失

`產生流水號` 目前用寫死的對照表換業務代碼：

```js
const SALES_CODE = { 'Ivan':'IV', ... };
const code = SALES_CODE[salesName];
if (!code) throw new Error('未知業務: ' + salesName);   // ← 整條 execution 掛掉
```

`Nick`、`Ian`、`Jason` 都在 `google-login` 的授權名單裡（能登入），但**不在這張表裡**，
一報刀就 throw → 整條流程中止 → 資料沒寫入、也沒回流水號。`River` 則是連業務代碼都沒有。

而「設定」分頁**早就有他們的業務代碼了**（Ian=IA、Nick=NI、Jason=JA），只有 n8n 這份副本沒同步。

**根治方式：不要再用硬編碼表，直接從「設定」分頁用姓名查。** 那個 node 本來就在讀「設定」，
資料在同一列，不用多讀一次；以後新增業務只要在 Sheets 加一列，不用動 n8n。

### 把 `產生流水號` 的 Code 整段換成這個

```js
const rows = $input.all().map(i => i.json);
const raw = $('手動報刀 Webhook1').item.json;
const webhookData = raw.body || raw;

// 多品項的第 2 筆以後：已經帶著第 1 筆產生的流水號，直接沿用。
// ⚠️ 這條路徑不可以檢查或增加額度——額度是「一張單算一筆」，
//    不是「一個品項算一筆」，否則三個品項的單會吃掉三筆額度。
if (webhookData['流水號']) {
  return [{ json: { ...webhookData } }];
}

const salesName = String(webhookData['業務'] || '').trim();
if (!salesName) {
  return [{ json: { success: false, code: 'NO_SALES', message: '缺少業務名稱' } }];
}

// 從「設定」分頁查這個人：業務代碼、訂閱方案、本週已用都在同一列，不用多讀 Sheets
const me = rows.find(r => String(r['姓名'] || '').trim().toLowerCase() === salesName.toLowerCase());
if (!me) {
  return [{ json: { success: false, code: 'UNKNOWN_SALES',
    message: `「${salesName}」不在「設定」分頁，請先在 Google Sheets 新增一列（姓名＋業務代碼）` } }];
}

const code = String(me['業務代碼'] || '').trim();
if (!code) {
  return [{ json: { success: false, code: 'NO_CODE',
    message: `「${salesName}」還沒有業務代碼，請在「設定」分頁補上` } }];
}

// ── 訂閱方案檢查 ──────────────────────────────
const WEEKLY_CAP = 7;
const plan = String(me['訂閱方案'] || '完整').trim() || '完整';   // 空白＝完整，不誤擋

if (plan === '停用' || plan === '未訂閱') {
  return [{ json: { success: false, code: 'NOT_SUBSCRIBED',
    message: '此帳號尚未訂閱，請聯絡 Ivan 開通' } }];
}

const used = Number(me['本週已用'] || 0) || 0;
if (plan === '陽春' && used >= WEEKLY_CAP) {
  return [{ json: { success: false, code: 'QUOTA_EXCEEDED', used, cap: WEEKLY_CAP,
    message: `陽春版每週上限 ${WEEKLY_CAP} 筆，本週已用 ${used} 筆` } }];
}

// ── 產生流水號 ────────────────────────────────
const lastSerial = String(me['最新流水號'] || '');
const now = new Date();
const yy = String(now.getFullYear()).slice(-2);
const mm = String(now.getMonth() + 1).padStart(2, '0');
const dd = String(now.getDate()).padStart(2, '0');
const today = yy + mm + dd;

let seq = 1;
if (lastSerial && lastSerial.substring(2, 8) === today) {
  seq = parseInt(lastSerial.substring(8), 10) + 1;
}
const newSerial = code + today + String(seq).padStart(2, '0');

// 回傳剩餘額度給前端顯示（完整版給 null＝前端不顯示額度標籤）
const remain = plan === '陽春' ? Math.max(0, WEEKLY_CAP - used - 1) : null;

return [{ json: { ...webhookData, '流水號': newSerial,
                  _plan: plan, _remain: remain, _cap: WEEKLY_CAP } }];
```

> `_plan` / `_remain` / `_cap` 這幾個欄位不會被寫進 Sheets——`寫入總表` 用的是
> `defineBelow` 明列欄位對應，沒列到的一律忽略。

### 加一個 IF node 把「被擋下來」的情況分流

**這一步不能省。** 上面的程式被擋時回傳的是 `{ success:false, ... }`、沒有流水號，
如果直接流到 `寫入總表`，會在主表 append 一列空白垃圾資料。

1. 在 `產生流水號` 和 `寫入總表` 中間插一個 **IF node**，命名「可以報刀?」
   - 條件：`{{ $json['流水號'] }}` → String → **is not empty**
   - **true** → 接 `寫入總表`（原本的連線）
   - **false** → 接一個新的 Respond node
2. 新增 **Respond to Webhook** node，命名「回傳無法報刀」
   - Respond With: JSON
   - Response Body：`={{ JSON.stringify($json) }}`

> 這跟你在作廢那條流程做過的「找到報刀單?」是同一個模式。

### 把 `回傳流水號` 的回應內容補上額度

Response Body 換成：

```
={{ JSON.stringify({ success: true, serialNo: $('產生流水號').first().json['流水號'], remain: $('產生流水號').first().json['_remain'], cap: $('產生流水號').first().json['_cap'], plan: $('產生流水號').first().json['_plan'] }) }}
```

前端會把 `remain` 存到 localStorage，下次進來就能在 topbar 顯示「本週剩 N 筆」，
**不需要另外做一支查額度的 webhook**。

## 六、已完成（前端，待後端接上才會生效）

`報刀_v2.html` 已經做好並測過：

1. **topbar 額度標籤**：陽春版顯示「本週剩 N 筆」，剩 ≤2 轉橘、0 轉紅；完整版不顯示。

   被擋後**不會繼續送出後續品項**。

### 為什麼上限訂 7 而不是 5

| 上限 | Derek 每月被擋 | 預估升級 | 月營收 | 淨利（成本 2,000） |
|---|---|---|---|---|
| 5 筆 | 7.2 筆 | 6/6 | 6,000 | +4,000 |
| **7 筆** | 2.1 筆 | 5~6/6 | 5,300~6,000 | **+3,300~4,000** |

純看數字 5 比較好，但**截圖交件**這個工作流程沒有反映在數字裡：被擋的人當下交不出截圖、要在群組裡用不同方式交件，痛感遠大於「月底多打兩行字」。納入這點後 7 也足以驅動升級，且方案看起來比較不像假選項。

### 為什麼不用「平均值」判斷誰適合陽春版

工作量是**陣發性**的。Derek 平均 4.6 件/週看起來完全符合 5 筆上限，但實際週分布是 `0,0,6,6,6,9,2,8`——8 週有 5 週超過 5 筆。用平均值設額度會嚴重低估衝擊。
